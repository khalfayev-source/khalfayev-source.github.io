Privacy Policy

Aquamaster AI Bridge · Effective 3 November 2026

HomePrivacy Policy

1. Who this policy covers

Aquamaster AI Bridge ("the application") is a personal tool that runs only on its owner's own Windows computer and connects only to the owner's own Google account. It is not offered to the public, has no other users, and refuses to sign in with any account other than the owner's. This policy describes how the application handles the Google user data it can access.

2. Google data the application accesses

PermissionWhat is accessed
drive.readonlyFile names, IDs, owners, types and creation times in the bridge's Commands and Results folders, and the text of command files in the Commands folder.
drive.fileResult documents that the application itself creates in the Results folder.
Account informationThe email address of the signed-in account, used only to confirm that it is the owner's account.

Although drive.readonly technically allows reading any file in the owner's Drive, the application only requests the folders configured for the bridge. Command files larger than 64 KB, and file types other than Google Docs and plain text or JSON files, are not read.

3. How the data is used

  • To read commands placed in the Commands folder and check them against a fixed list of allowed command types.
  • To answer allowed read-only status and diagnostic commands by creating a result document in the Results folder.
  • To queue any other request for the owner's own review, with a notification on the owner's computer and a short notice document in the Results folder that does not contain the request text. Such requests are not carried out automatically.
  • To reduce the risk of processing the same command twice, by checking a local log and the titles of existing result documents.

Google data is not used for advertising, profiling, analytics or any purpose other than operating the bridge for its owner. It is not used to train AI or machine learning models.

4. Sharing and transfer

The application does not sell, rent or share Google user data with anyone. It has no server of its own and sends no data to any third-party service; it communicates only with Google's APIs. Command files and results stay in the owner's Google Drive and on the owner's computer. The owner may separately choose to review a queued request with an AI assistant of their own; that is a manual action by the owner and not something the application does.

The use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

5. Storage and retention

All data the application keeps is stored on the owner's computer:

  • copies of downloaded command files;
  • a processing log with command IDs, Drive file IDs, file titles, result status and timestamps;
  • copies of the result documents it created;
  • a list of queued requests (command ID, Drive file ID and time);
  • an operational log of each check (start and end time, number of commands, errors);
  • the OAuth sign-in credentials described in section 6.

These local files are kept until the owner deletes them; the application has no automatic deletion schedule. Result documents in Google Drive remain in the owner's Drive until the owner deletes them there. The application itself never deletes or moves files in Google Drive.

6. Security

  • Sign-in uses Google's OAuth 2.0 flow for desktop applications with PKCE and a state check, through a temporary local address on the owner's computer.
  • The OAuth refresh token is stored encrypted with Windows Data Protection (DPAPI), so it can only be decrypted by the owner's Windows user account on that computer. Access tokens are kept in memory only.
  • The OAuth client file and token are kept in a local folder that is excluded from source control.
  • All communication with Google uses HTTPS.
  • Each request to Google is checked against a fixed list of allowed operations. The application contains no code to delete, trash, share, copy or edit existing Drive files, or to change file permissions.
  • The owner can stop the application at any time with a local stop switch.

No method of storage or transmission is completely secure, and these measures cannot guarantee absolute security.

7. Revoking access and deleting data

  • Access can be revoked at any time in the Google Account under Third-party apps & services.
  • The application also has a local command that revokes its token with Google and deletes the stored token from the computer.
  • Local copies and logs can be deleted by the owner from the computer. Result documents can be deleted by the owner in Google Drive.

8. Changes to this policy

If the way the application uses Google data changes, this page will be updated and the effective date above will change.
